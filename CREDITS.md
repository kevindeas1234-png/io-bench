## How this was made

The code, tests and documentation were generated by a locally-run language model working
through **LM Studio Bionic**, an agent harness able to read files, edit them and run
commands on this machine, under the author's direction.

- **Human role:** chose the goal; imposed the constraints; decided scope and refusals;
  judged whether output was correct; reviewed and accepted each step; owns the result.
- **Agent role:** wrote the code, ran builds and tests, diagnosed failures, wrote the
  documentation and the evidence tooling (`verify.py`, `history.py`, `bank.py`).

This is recorded here rather than left implicit because it is material to how the work
should be read.

## What the logs establish — and what they do not

Precision matters more here than reassurance.

**They establish:**

- The work happened on one machine, on known dates. `D:\AOS_Logs\broker.log`,
  `bank.log`, `D:\ANVIL_Logs\history.log`, the kernel serial logs in `D:\OS\logs\`, and
  git commit timestamps all agree.
- The work evolved rather than appearing fully formed: ten numbered bank snapshots and
  roughly thirty source snapshots record the state at each stage.
- The claims are true. `verify.py` compares the kernel's own serial output against hashes
  computed independently on the host, and reports `RESULT: PASS`.

**They do not, by themselves, prove authorship.** A log shows that work ran; it does not
show who directed it. Anyone can run tests against someone else's code.

**The stronger evidence is the record of decisions**, in this order:

1. **Session transcripts** — the questions asked, the corrections demanded, the scope
   calls made. This is the direct evidence of authorship: it shows the reasoning that
   shaped the code, not merely that the code ran.
2. **`D:\AOS\WORKLOG.md`** — a dated, first-person account of what changed and why,
   including the wrong turns.
3. **Git history** — commit authorship and timestamps, one author across all three
   repositories.
4. **The bank snapshots** — provable intermediate states, each hash-verified.

Keep the transcripts. They are the strongest thing you have, and unlike a log they can
only have come from the person at the keyboard.

**`D:\AOS_Evidence\`** holds exactly that: the exported conversation (2,684 entries, from
the first message onward), a byte-level snapshot of the session database taken with
SQLite's online backup, LM Studio's record of every completion it served, and a manifest
of SHA-256 hashes for the lot. Redacted copies sit alongside the raw ones for showing to
other people. Note that the raw pack contains a pasted API credential — it is private, and
the token should be rotated.
